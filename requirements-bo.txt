# Environment mirror for the preemptible cloud box `bo`.
#
# Every version here was read off `pip freeze` on the workstation on 2026-08-16, so a campaign run
# there and a campaign run here are the same experiment. Pinning matters most for jax/XLA, which
# decides the numerics; the rest are pinned for the same reason, not because they were suspected.
#
# jax-cuda13 is the workstation's own choice AND what this card needs: the RTX PRO 6000 Blackwell is
# sm_120 and requires CUDA 13, which driver 580.173.02 provides. There is no compromise between
# mirroring and running here. Note the box's driver is OLDER than the workstation's (580.173.02 /
# CUDA 13.0 against 595.84 / CUDA 13.3); the pinned NVIDIA wheels are all 13.0.x, so a CUDA 13.0
# runtime on a >= 580 driver is in spec, and the mirror works BECAUSE of the pins, not despite them.
#
# THE NVIDIA WHEELS ARE PINNED EXPLICITLY AND MUST STAY THAT WAY. `jax-cuda13-plugin` alone does not
# pull them: it declares them only under an extra, so pinning the plugin by version installs a
# plugin that then cannot find cuDNN and jax falls back to CPU with a warning, not an error. That is
# what happened on the first provisioning attempt here, and only the acceptance assert caught it.
# The unsuffixed `nvidia-*` names ARE the CUDA 13 series (NVIDIA dropped the suffix at 13); the
# `-cu13` ones are those that kept it.
#
# NOT mirrored, deliberately: the workstation's snakemake SLURM executor plugins (this box has no
# SLURM -- Snakefile.cloud drives it locally), and the ~300 packages in the workstation env that
# detopt never imports.
#
# Transitive dependencies are left to pip. `scripts/provision_bo.sh` diffs the resulting freeze
# against the workstation for everything detopt imports, and reports a divergence rather than
# hiding it.
